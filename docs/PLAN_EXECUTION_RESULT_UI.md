## 2. 需求冻结清单（必须逐条满足）

## 2.1 执行结果页布局

- 顶部左侧：`日期：yyyy年M月d日`（可任意切换日期，默认当天）。
- 顶部中间按钮：`立即停止/接续开始`、`重新发送此轮任务`、`重试所有失败项`、`简略视图`。
- 顶部右侧小框：循环计划（可查看详情、可删除）。
- 发送列表仅保留两块并列：
  - `正在执行计划`（当天已开始计划，含已发完计划）
  - `当日待执行计划`（当天未开始的一次性计划）

## 2.2 日期与按钮生效域

- 两块列表都只显示当前选中日期数据。
- 顶部发送控制按钮仅控制当前选中日期上下文中的目标计划。
- 切到其他日期不影响后台实际发送，仅改变可见内容与按钮可用性。

## 2.3 展示与折叠

- 默认：计划、联系人、消息全部展开。
- 支持两级折叠：联系人级、计划级。
- `简略视图`：一键折叠到“仅计划”层级，再次点击恢复展开。
- 折叠后不显示行内 `重新发送`。

## 2.4 间隔展示

三类间隔都要清晰标注（只读）：

- 同联系人消息间隔
- 联系人切换间隔
- 素材包内部间隔（展开时）

编辑页与待执行详情保留可编辑能力。

## 2.5 发送状态

状态仅使用：

- `30%`
- `70%`
- `发送成功`
- `发送失败`
- `已暂停`

说明：百分比是阶段信号，不是上传字节进度。

## 2.6 暂停/接续语义

- 停止请求后，当前发送调用先返回，再决定暂停落点。
- 当前条已发出成功：暂停点移到下一条未发送消息。
- 当前条未发出成功：暂停点停在当前条。
- 接续从暂停点继续；已成功项不重发。
- 包内暂停时，接续从包内下一条未发送素材继续。

## 2.7 素材包规则

- 加入素材包继续使用现有两种方式：`展开为多个步骤` / `作为一个原子节点`。
- 编辑页和执行结果页都必须是同样层级结构（包标题下挂子项）。
- 展开模式：默认展开，显示包内间隔，发送按计划快照。
- 原子模式：默认收起，可双击查看内部详情。
- 原子包内单条失败：
  - 该条标 `发送失败`
  - 包外层同步标失败（避免用户漏看）
  - 继续发送包内下一条

## 2.8 双击查看详情

任何页面的任何消息（散消息、包内消息）双击均可查看消息详情（复用现有预览能力）。

## 3. 数据模型改造计划

## 3.1 `BroadcastPlan`

新增：

- `name: str = ""`

规则：

- 用户未填写时，提交前自动回填调度说明作为名称。
- 旧计划缺失该字段时按空字符串兼容。

## 3.2 `BundleStep`

扩展字段：

- `presentation: "atomic" | "expanded"`（默认 `atomic`）
- `items: list[...]`（仅 expanded 使用）
- `item_gaps: list[float]`（仅 expanded 使用）

兼容策略：

- 老结构仅含 `bundle_id` 时按 `atomic` 处理。
- 读取旧数据后可按新结构编辑并回写。

## 3.3 报告记录字段

每条记录统一具备：

- `step_index`
- `inner_index`（非包内为 `-1`）

`plan_meta` 扩展：

- `name`
- `started_at`

读取旧报告时的兼容回退：

- 无 `inner_index` -> `-1`
- 无 `started_at` -> 通过既有时间字段/文件时间推导

## 4. 发送执行链路计划

## 4.1 发送单元层（`send_units.py`）

目标：把“联系人 x 消息”统一展开成可执行单元序列，供执行器与 UI 共用。

单元需包含：

- 联系人上下文（索引、名称）
- 顶层步骤索引与包内索引
- 真实可发送叶子步骤
- 层级归属信息（是否属于某个素材包）
- 间隔信息（同联系人间隔、换人间隔）

## 4.2 阶段状态发射

每单元固定发射：

1. `prepare` -> UI 显示 `30%`
2. `sending` -> UI 显示 `70%`
3. `result` -> 成功/失败/暂停

## 4.3 失败策略

- 失败即标记，立即跳过，继续后续单元。
- 禁用原“自动重试两次”逻辑。
- 原子包内失败不终止整个包；继续包内下一条。
- 同步写包外层失败聚合状态。

## 4.4 暂停策略

- `stop_event` 在单元边界与包内边界生效。
- 已进入发送调用时不强杀，等待返回后落位。
- 根据调用结果确定暂停停在“当前条”或“下一条未发送条”。

## 4.5 接续与重试策略

- 接续从暂停点继续。
- 行内 `重新发送` 仅重发当前单元。
- 顶部 `重试所有失败项` 收集当前计划失败单元批量重发。
- 本轮仍在发送时，重发动作排队，提示：
  - `重新发送将在本轮消息发送结束后开始`

## 5. 编辑页改造计划（`plan_composer.py`）

## 5.1 计划名称输入

- 在“参数与调度”区新增计划名称输入框。
- 允许留空；提交时统一回填默认名称。

## 5.2 素材包层级展示

- 展开模式插入：包标题 + 子步骤 + 包内间隔。
- 原子模式插入：包标题（默认折叠）。
- 双击行为：
  - 包标题：展开/收起内部
  - 消息行：打开消息详情预览

## 5.3 组内编辑约束

- 包标题拖拽时整组跟随。
- 子步骤仅允许组内排序。
- 删除包标题时整组删除。
- 间隔修改写入规则：
  - expanded -> 计划快照
  - atomic -> 素材库对应素材包

## 5.4 计划构建输出

- expanded 生成 `BundleStep(presentation="expanded", items, item_gaps)`
- atomic 生成 `BundleStep(presentation="atomic", bundle_id, bundle_name)`

## 7. 执行结果页改造计划（`run_monitor.py` + `send_board.py`）

## 7.1 职责拆分

- `run_monitor.py`：数据协调、状态机、线程信号、动作处理。
- `send_board.py`：层级渲染、折叠、行按钮、双击/右键事件。

## 7.2 顶栏交互

- 日期切换触发两块列表重载。
- 四按钮行为：
  - `立即停止` / `接续开始`
  - `重新发送此轮任务`
  - `重试所有失败项`
  - `简略视图`
- 除简略视图外，所有发送控制按钮均先确认。

## 7.3 数据来源

- 正在执行计划：当天 `started_at` 命中报告 + 当前内存实时状态。
- 当日待执行计划：`PendingPlanStore` 中当天且 `mode != cron` 项。
- 循环小框：所有 `mode == cron` 项（不受日期筛选）。

## 7.4 行状态展示

- 按层级渲染：计划 -> 联系人 -> 消息/素材包 -> 包内消息 -> 间隔行。
- 折叠状态下也要保证失败可见。
- 原子包外层聚合状态按“包内失败可见优先”。

## 7.5 事件分发

- 行内 `重新发送`、`接续开始` 事件回抛给 `run_monitor.py` 执行。
- 待执行与循环计划保留详情/删除入口。
- 双击任意消息节点打开详情预览。

---

## 8. 按钮行为实施规则

统一确认框（简略视图除外）：

- `立即停止`
- `接续开始`（顶栏/行内）
- `重新发送此轮任务`
- `重试所有失败项`
- 行内 `重新发送`

启用/禁用原则：

- 无运行且无暂停时：`立即停止`、`重新发送此轮任务` 禁用。
- `重试所有失败项`仅在符合上下文时可用（本轮运行中可排队，或按策略限制）。
- 恢复后按钮文案与状态及时回切。
